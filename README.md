# NekoFM 🐋

[![License](https://img.shields.io/badge/license-Apache%202.0-blue.svg)](LICENSE)
[![CI](https://github.com/7starsseeker/nekofm/actions/workflows/ci.yml/badge.svg)](https://github.com/7starsseeker/nekofm/actions/workflows/ci.yml)
![Platform](https://img.shields.io/badge/platform-Windows%20x64-lightgrey)
![Node](https://img.shields.io/badge/node-%E2%89%A522-brightgreen)

B站直播用的**音乐播放 + 实时歌词**系统。用你自己的网易云 VIP 账号放歌，弹幕点歌，
歌词逐句同步显示在直播画面上。

替代「闭源收费的点歌机插件」——播放、队列、歌词、叠加层全部本地可控。
**运行时零第三方依赖**（只用 Node 内置模块 + Electron）。

📖 [配置说明](docs/CONFIGURATION.md) · [架构说明](docs/ARCHITECTURE.md) · [更新日志](CHANGELOG.md) · [参与贡献](CONTRIBUTING.md)

```
弹幕 ──► 指令解析 ──► 点歌队列 ──► 音源解析 ──► 播放核心(<audio>) ──► VoiceMeeter ──► 直播
                                        │
                                        └──► 歌词时间轴 ──► SSE ──► 叠加层(直播姬浏览器源)
```

## 2. 为什么是这样设计的（踩过的坑）

这几条都是本机实测得出，改动前请先看理由：

1. **歌词同步不能依赖 Windows SMTC。** 很多播放器只在播放/暂停时推送时间轴，
   长播会漂移。本项目的时基是播放器自己的 `<audio>.currentTime`，10Hz 上报 +
   前端 rAF 插值，精度有保证。
2. **网易云会员曲免登录只能放 45 秒。** 实测 `fee=1` 曲目返回
   `freeTrialInfo:{start:0,end:45}`，ffprobe 量得 45.024s（完整应为 256s）。
   所以必须登录——本项目用 **eapi 原生扫码登录**，不需要伪造浏览器。
3. **登录类接口必须走 eapi。** 摘要按 `/api/...` 计算，但请求要发到 `/eapi/...`；
   写成 `/api/` 会得到 `400 参数错误`。老 `weapi` 对登录接口已失效。
4. **逐字歌词必须用 v1 端点。** 老接口 `/api/song/lyric` 的 `klyric`/`yrc` **恒为空**。
5. **B站音频有防盗链。** 不带 `Referer: https://www.bilibili.com` 直接 `403`；
   浏览器的 `<audio>` 无法自定义请求头，所以内置了 `/stream/bili` 代理做头注入。
6. **B站弹幕接口需要 WBI 签名**，不签名返回 `-352` 风控；签名后**完全免登录**。
   但拿到 token 还不够：**弹幕 WebSocket 必须由真实浏览器发起**。B站认的是
   "客户端实现本身"——Electron（UA / UA-CH 全套伪装、Chromium 130 与 152、
   升到 Electron 44 都试过）与 Node 直连一律被拒：握手 101 之后立刻 `1006`，
   连 B站自家页面的弹幕连接在 Electron 里都不建立。所以 NekoFM 会拉起
   **系统 Edge**（没有则 Chrome）开一个屏幕外的窗口当通道，用 CDP 在里面跑
   弹幕客户端，收到的原始包再回主进程解包。签名算法仍在 Node 侧，
   只是"发请求"这一步发生在浏览器里。**因此机器上要装 Edge 或 Chrome**
   （Windows 自带 Edge，通常不用管）。
7. **歌词不要只在变化时推送。** 直播姬的浏览器源可能在任何时刻加载/刷新，
   必须在 SSE 建连时补发当前歌词，否则晚接入的叠加层一直空白。
8. **引擎不会打断正在播放的歌。** 新点歌只入队；空闲时才自动开播。
9. **ffprobe 的标签键是 `format.tags`，不是 `format.format_tags`。**
   命令行里的 `format_tags=` 只是取值语法，不体现在 JSON 键名上（读错就拿不到歌名/艺术家）。
10. **`locate()` 在歌曲未开始时返回 `index = -1`（无当前行）**，叠加层据此显示
   "即将到来"的歌词而非把第一行当成正在唱。做歌词时间轴相关的断言时，
   探针必须落在**本行区间内**。
11. **逐字（yrc）染色已下线 —— 别再按"逐字"去理解渲染层。** 2026-09-26 按用户要求
   去掉了逐字功能：叠加层不再做"每个字按进度揭开"，**当前行只用「高亮色 + 加粗 + 投影」**
   区分，其余行变暗。歌词数据里的逐字时间戳**仍然照常解析**（`lrc.js` 的 `words` 字段还在），
   只是不再用于渲染 —— 将来要恢复，落点在 `overlay.js` 的 `buildWindow` + `overlay.css`
   里那段被注释掉的 `.line.karaoke` 说明。主题也因此只剩两个：
   `scroll`（单行滚动 + 当前行高亮）与 `dual`（双行 + 翻译）。
12. **浏览器急兑不是"在浏览器里放歌"。** 若让浏览器自己播，进度就得从页面里刮，
   歌词同步立刻失去精度；正确做法是借会话**取直链**，再交回自家播放核心。
13. **搜索接口不给封面 `picUrl`，只给 `picId`。** 只靠搜索结果封面会全空，
   要用 `picId` 反推（算法已用 `/api/song/detail` 的返回值逐字符校验过）。
14. **B站封面在部分客户端环境会瞬失败**（实测 Playwright 里 11ms 直接 error，
   而服务端 fetch 同一 URL 正常）。所以封面也走本地代理，并顺手要 240px 缩略图
   （原图 4500×2813 / 1.26MB → 7.4KB，小 170 倍）。
15. **数据目录跟随程序目录**（`<程序目录>/data`），Electron 的 `userData` 也在
   `app.setPath` 里改过去 —— 否则它会默认写 `%APPDATA%`，整套东西就没法"整个丢在 T 盘"。
16. **自检项必须无副作用。** 曾经因为"演示模式"检查留下 6 秒演示，
   污染了后续断言；现在检查完一律收尾还原，想持续观察请用「开始演示」按钮。
17. **`.bat` 里绝对不能写中文。** `cmd.exe` 按**控制台代码页**（中文系统是 936/GBK）
   解析批处理文件的字节，而文件通常是 UTF-8 —— 中文必然乱码；更糟的是某些字节
   会被当成命令分隔符，cmd 会把中文当命令去执行（实测刷一屏
   `'…' 不是内部或外部命令`）。本项目的规定：
   **`.bat` 只留纯 ASCII + CRLF**，所有本地化文字由 Node 脚本打印
   （[tools/start.js](tools/start.js) / [tools/headless.js](tools/headless.js)），
   批处理里 `chcp 65001` 之后再调 node 即可正常显示中文。
   测试中心有专门的回归检查（「批处理脚本编码安全」）防止再犯。
18. **启动器本身也要能被测。** `tools/start.js` 支持 `--check-only`：
   只做环境自检、不拉起 GUI。否则"测一下启动脚本"会真的弹出应用窗口
   （踩过：一次检查就留下 8 个 Electron 进程在桌面上）。
19. **网易云会按 IP 限流，要能优雅降级。** 密集请求后会收到
   `code:405 "操作频繁，请稍候再试"`（实测不同操作系统同时中招，
   同一公网 IP）——这是外部状态，不是程序缺陷。应对：
   - `NeteaseClient._fetch` 对 405/429 做**带退避的自动重试**（最多 3 次），其余错误立即返回
   - 测试中心遇到限流把该项标为**「跳过」并写明原因**，而不是判失败
   - `test/e2e.test.js` 有**联网预检**：限流时整体 SKIP（退出码 0）并说明，不刷一屏红

   自检工具谎报军情比不报更糟 —— 这条是设计原则，不是权宜之计。
20. **`/stream/local` 必须走白名单。** 加了「打开本地音乐」之后，这个接口
   从"只服务曲库目录"变成"要服务用户随手选的文件"，如果不校验，
   `/stream/local?path=` 就是**任意文件读取**（直播机上的任何本地网页都能探文件）。
   现在的口径：**曲库目录 + 用户显式打开的文件 + 封面缓存目录**，
   与 `/stream/cover` 共用同一份白名单（`LocalLibrary.streamAllowList()`）。
21. **歌词匹配失败不能静默。** 本地曲目若没有侧车/内嵌歌词，会回落到
   "按歌名搜网易云"；失败时引擎会记 `lastLyricDiag`（歌名/关键词/原因），
   界面上能说清"为什么这首没歌词"。测试也据此区分：
   **有解释的失败 = 外部状态（跳过），静默失败 = 真 bug（判失败）**。
22. **队列自己的去重会挡掉"内部回填"。** `SongQueue` 有自己的近期去重历史
   （防止观众重复点同一首），但列表循环回填历史、上一首回退这些
   **引擎内部**操作，回填的恰恰是"刚放过"的歌 —— 结果一首也进不来，
   列表循环等于失效。为此给 `push` 加了 `force` 选项：
   内部调用绕过去重/冷却/每人上限，但**仍然尊重容量上限**，也**不影响
   主播/房管越过上限**这个既有行为（这条也踩过：一改就把主播权限弄丢了）。
23. **播放列表可以移除，但"正在播放"不算队列项。** `queue.clear()` 刻意
   保留 `current`，所以测试里复现同一首歌时会被判重；要清干净得连
   `current` 与 `queue.history` 一起复位（写测试时踩过）。
24. **Windows 上"窗口黑着不显示"要按三层防。** 实测症状：菜单能点、DOM 正常、
   `webContents.capturePage()` 能导出完整界面，但屏幕上是空的，点"强制重绘"也没用。处置：
   - 禁用 Chromium 的**原生窗口遮挡计算**（`disable-features=CalculateNativeWinOcclusion`）：
     它判定窗口被遮挡时会**直接停止绘制**
   - 窗口**先 `show:false`，`ready-to-show` 之后再 show()**：
     创建即可见的话，首帧提交可能被丢掉
   - 加载后**主动催一次重绘**（1px 尺寸微调 + `invalidate()`）
   - 默认关闭硬件加速（纯 2D 界面够用；`--gpu` 或 `NEKOFM_GPU=1` 可开回来）
   - 菜单给「修复画面（hide→show + reload）」，用户能自救
   **兜底**：控制台本身就是网页，浏览器直接打开 `http://127.0.0.1:37821/` 一样能用。
25. **监听要先挂、再 `loadURL`。** 反过来的话（先 `loadURL` 再 `once('did-finish-load')`），
   本地页面加载太快时事件已经过去，标志位永远设不上 —— 表现为"页面加载完成"
   偶发失败，而且**没有** `did-fail-load` 可供排查。隐藏窗口尤其容易撞上。
26. **无边框窗口必须自带关闭入口。** 叠加层预览窗是 `frame:false` + `alwaysOnTop`，
   没有系统关闭按钮；不给入口用户就关不掉（被吐槽过）。做法：主进程用
   `?preview=1` 加载，页面据此显示工具条（关闭/重载/拖动区）；
   直播姬的浏览器源不带该参数，所以正式画面里永远不会出现这些控件。
27. **绿色版与开发版的数据是"联接"关系，而打包会把它弄丢。**
   绿色版读 `release/win-unpacked/data`，开发版读项目根的 `data/`；
   靠一个**目录联接**（Junction）让前者指向后者，两边才共用配置/缓存/登录态。
   但 `electron-builder` 每次打包都清空重建 `release/` —— 联接跟着消失，
   绿色版随后在 exe 同目录**新建一份空 `data`**。用户看到的就是
   "**双击 exe 之后信息全丢**"（真实踩过），而开发版那份其实一点没动。
   所以 `npm run pack`（本机用）要建联接、`npm run pack:release`（出发布包）
   在打完 zip 之后**补建**联接；发布 zip 则在建联接**之前**打，且
   `tools/make-release-zip.js` 会跳过一切重解析点并自检"无 data/"。

## 3. 安装与运行

### 前置

- **Windows 10/11**，Node.js ≥ 22
- FFmpeg（本地曲库元数据/歌词提取用；`ffprobe` 需在 PATH）
- 可选：VoiceMeeter / VB-Cable（音频路由，**由你自己接**，程序不设计音频路由）
- **弹幕功能需要下面两者之一**（详见 [弹幕通道怎么选](#弹幕通道怎么选)）：
  - 系统 **Edge 或 Chrome**（Windows 自带 Edge，通常不用管）—— 走浏览器通道，免登录、可连任意直播间
  - 或 **自备 B站直播开放平台开发者凭证** —— 走官方通道，最稳，但**凭证要自己申请**

### 弹幕通道怎么选

这是**唯一一项需要按自己环境决定**的配置。两条通道能力边界完全不同：

| | 官方通道 `openlive` | 浏览器通道 `browser` |
|---|---|---|
| 需要什么 | **自己申请**的开发者凭证（accessKey + appId + 主播身份码） | 本机装有 **Edge 或 Chrome** |
| 能连哪个房间 | **只能是自己**（由主播身份码绑定） | **任意**直播间（`roomId` 生效） |
| 依赖浏览器 | 不需要 | 需要（拉起系统 Edge/Chrome，屏幕外窗口） |
| 稳定性 | 最稳（官方接口，不碰网页端风控） | 可用，但依赖本机浏览器存在 |

> ⚠️ **`openlive` 不是"填个开关就能用"。** 开放平台面向开发者，需要：个人开发者认证 →
> 创建项目并通过审核（约 3~5 个工作日）→ 生成主播身份码；而且
> **弹幕（DM）等消息类型必须单独向 B站运营申请开通**，否则会"连上了但一条弹幕都收不到"。
> 凭证没配全时程序**会自动回落到浏览器通道**并在界面提示，不会连不上 ——
> 但也不会凭空获得开放平台能力。

> ⚠️ **`browser` 通道要求本机有 Edge 或 Chrome。** B站的弹幕 WebSocket 只认真实浏览器
> （Electron / Node 直连握手后被判死），所以程序必须拉起系统浏览器来收。
> **两者都没装的机器用不了这条通道**，这种情况只能去申请官方凭证。

申请步骤与全部字段说明见 [docs/CONFIGURATION.md](docs/CONFIGURATION.md#2-b站bilibili)。

### 安装

**方式一：下载发布包（推荐，不用装 Node）**

到 [Releases](https://github.com/7starsseeker/nekofm/releases) 下载 `NekoFM-<版本>-win-x64.zip`，解压到任意目录，
双击 `NekoFM.exe` 即可（绿色版，数据全在 exe 同目录的 `data/`，整个文件夹拷走就能换机）。

**方式二：从源码跑**

```bat
cd <项目目录>
npm install
npm start
```

不装 Electron 也能跑（降级模式，用任意浏览器当播放核心）：

```bat
node tools/headless.js
```

### 部署到别的目录

```bat
node tools\deploy.js D:\nekofm --install
```

`tools/deploy.js` 是**只增不删**的部署脚本：

- 自动排除 `node_modules`、`data`、`.git`、`*.log` —— 目标端的配置、缓存、
  **网易云登录会话**都不会被覆盖
- 内容相同的文件会跳过（`--verbose` 可看清单，`--dry-run` 可先预演）
- `--install` 会在目标目录装依赖（已有 Electron 则跳过）
- 内置安全闸：拒绝把源目录本身或它的上级作为目标

换机器、换盘都只要这一条命令。

### 打包（本机绿色版 vs 发布包）

两条命令，用途不同 —— **别搞混，混了会以为"数据全丢"**：

```bat
npm run pack           :: 本机跑绿色版用：打包 + 自动建立"数据联接"，与开发版共用同一份 data
npm run pack:release   :: 出发布包用：打包 + 打干净 zip（不含 data）+ 之后再补建联接
```

**为什么需要"数据联接"**：绿色版的数据目录是 `release/win-unpacked/data`，
开发版是项目根下的 `data/`。想让两边看到同样的配置、缓存、登录态，
就把前者做成**指向后者的目录联接（Junction）**——`tools/link-data.js` 干这个。

> ⚠️ **`electron-builder` 每次打包都会清空重建 `release/`，联接跟着消失。**
> 联接一没，绿色版就会按自己的逻辑在 exe 同目录**新建一份空 `data`**——
> 默认配置、空缓存、没有登录态，看起来就像「**信息全丢**」。
> **其实你的东西一点没动**，只是绿色版去读新空目录了。
> 恢复：删掉那份新建的空 `data`（或改名挪走），再跑 `npm run link-data`。
>
> 发布 zip **必须**是干净的（不含 `data/`），所以它是在建联接**之前**打的 ——
> `tools/make-release-zip.js` 会主动跳过一切重解析点（联接/符号链接），
> 并在包成后自检「包内无 `data/`、无 `config.json`、无 `Cookies`」，命中就直接中止。

启动后：

| 用途 | 地址 |
|---|---|
| 控制台 | `http://127.0.0.1:37821/` |
| 播放核心 | `http://127.0.0.1:37821/player` |
| **歌词叠加层** | `http://127.0.0.1:37821/overlay` |

### 接进直播姬

1. 启动 NekoFM，保持运行
2. 直播姬 → 添加素材 → **浏览器源 / 网页**
3. 地址填 `http://127.0.0.1:37821/overlay`
4. 建议尺寸 **1280 × 360**（高度决定能显示几行；`行数` 可在控制台调）
5. 背景天然透明，不需要抠色

> 也可以用「窗口采集」抓 NekoFM 的叠加层预览窗（控制台里点「叠加层预览窗」）。

### 音频（VoiceMeeter）

播放核心是一个独立进程，输出设备在控制台「播放核心 / 输出设备」里选，
或打开播放核心窗口用下拉框选：

- 想**只让观众听**：输出到 `CABLE Input`，直播姬/调音台里取 `CABLE Output`
- 想**自己和观众都听**：输出到 `VoiceMeeter Aux Input`，在 VoiceMeeter 里
  把 AUX 同时送 A1（你的耳机）与 B1（推流通道）

播放核心窗口里有「测试音（1kHz）」，用来确认路由接对了。

## 4. 弹幕指令

默认词表（`data/config.json` 里的 `commands` 可改）：

| 指令 | 说明 |
|---|---|
| `点歌 歌名` | 网易云搜第一首并排队 |
| `点歌 ID 1234567` | **按网易云歌曲 ID 直接点**（不搜索、不会配错成同名的另一首）。大小写不敏感，必须有空格 |
| `点歌 本地 歌名` | 从本地曲库找 |
| `点歌 b站 关键词` | B站搜视频，放它的音频 |
| `点播 BV号` / 直接发 BV 号 / 发视频链接 | 点 B站视频。**自动识别**裸 BV 号、`av` 号、网页链接、`b23.tv` 短链；小写 `bv` 前缀也会被规范成大写（B站只认大写，但观众手打常是小写） |
| `切歌` / `跳过` | **点歌本人可切自己的歌**；主播/房管随便切；其他观众会被拒（见 §7 切歌权限） |
| `撤歌 2` / `撤歌` | 按序号撤 / 撤自己最后一首 |
| `我的` | 查自己在队列的位置 |
| `队列` | 查队列 |
| `歌词 开` / `歌词 关` | 需房管或主播 |
| `音量 80` | 需房管或主播 |

队列规则：每人最多 `perUserMax` 首、冷却 `cooldownMs`、同一首在
`dedupeWindowMs` 内去重；主播/房管可插队、可越过队列上限。

## 5. 歌词叠加层样式

**2 种主题**，控制台里切换即时生效（无需重启直播姬）：

| 主题 | 效果 |
|---|---|
| `scroll` | 单行滚动：纯原文，**当前行高亮**，其余行变暗 |
| `dual` | 双语：双行（原文 + 中文翻译），可选罗马音 |

可调：字号、字号是否随源尺寸缩放、透明度、歌词底板不透明度与**底板颜色**、
正文色、高亮色、描边色/描边宽、歌词偏移（毫秒）、翻译/罗马音/信息卡开关。

**「当前行」是怎么区分的**：只靠**高亮色 + 加粗 + 一层轻微投影**，不做逐字染色
（逐字功能已于 2026-09-26 下线，理由见第 2 节第 11 条）。因此：

- **正文色**作用于**非当前行**（当前行恒用**高亮色**，不受正文色影响）
- 歌词数据里的逐字时间戳仍会解析，只是不再用于渲染

## 7. 播放器

### 播放模式

| 模式 | 行为 |
|---|---|
| `order` 顺序播放 | 按队列顺序放，放完就停 |
| `repeat-all` 列表循环 | 队列空后把**历史重新排回队列**继续播 |
| `repeat-one` 单曲循环 | 一直重播当前这首（手动切歌才会真换） |
| `shuffle` 随机播放 | 从队列里随机抽一首 |

控制台「正在播放」卡片里切换，也可 `POST /api/command {"action":"setPlayMode","mode":"shuffle"}`。

### 传输与控制

上一首（走播放历史）· 播放/暂停 · 下一首 · 进度条**点击/拖动跳转** ·
音量 · 静音 · 收藏（收藏列表可当闲时歌单音源）。

### 切歌权限（弹幕）

队列里每一项都记录了**是谁点的**，切歌规则：

| 谁 | 能否切 |
|---|---|
| 主播 / 房管 | ✅ 随便切 |
| **点歌本人** | ✅ 只能切**自己点的那首** |
| 其他观众 | ❌ 会被拒并回一句原因 |
| 你在工具本地（控制台 / API） | ✅ 无条件可切（不受上述限制） |

配置项 `queue.danmakuSkip.ownOnly`：设为 `false` 则观众一律不能切（连本人也不行）。

### 队列逐项操作

每个队列项右侧：**顶**（提到最前）· 类型下拉 + **拉黑** · **撤**。
拉黑支持四种粒度：**歌曲 / 标题关键词 / 歌手 / BV号** ——
拉黑后会**同时把这一项从队列里撤下**（拉黑的本意就是不想让它播）。

### 闲时歌单（没人点歌时不冷场）

队列空了就自动接着播。**音源是「已保存播放列表」**（唯一来源 —— 早期版本可以在
网易云歌单 / 本地曲库 / 收藏之间三选一，现在统一到这一张手动维护的列表上）。

**「直播中」按钮就是它的开关**，行为如下：

- 切到「直播中」时如果**当前什么都没在播 → 立刻开始播闲时歌单**（不用再手动点一首）
- 直播中**仅限闲时**可以在已保存列表里自由手动选曲：正在播闲时歌单、或此刻空闲时，
  点任意一首都会切过去；但正在播**观众点的歌**时会被拦下（点歌优先，等闲时接管）
- 切到「未直播」时它变回一张普通歌单，随时可点播

另有「随机顺序」与「近期不重复 N 首」。点歌一进来就会盖过它。

### 在线媒体缓存

在线放过的歌会**在后台落盘**到 `data/cache/`：

- 首次播放仍走远端直链 —— **不为了让缓存而多等一秒**
- 下次点同一首直接读本地文件，不受网易云直链 20 分钟过期影响
- **45 秒试听片段绝不缓存**（否则以后一直只能放那半首）
- 按总量上限 LRU 淘汰（默认 2GB，单文件 ≤120MB）
- **启动不逐条扫盘**：缓存目录里有一份集中索引 `index.json`，启动只读它（实测 3000 条 9ms；
  逐条读边车要 1485ms）。边车 `.json` 仍是真相源 —— 索引与磁盘对不上或损坏时，
  自动回落逐条扫描并重建，不会丢数据
- 控制台可看最近缓存、清空、开关；`data/cache/` 在流接口白名单内
- **清理非已保存缓存**：一键删掉"缓存里有、但不在已保存列表/收藏里"的曲目。
  直播间随手点的一次性曲目最占地方，2GB 很容易被它填满、再把常听的那批挤掉 ——
  这条就是为此。删之前先报"将清理 N 首 / X MB"，确认后才动手；正在播放的会自动跳过。

**B站曲目的缓存键是 `bilibili-<bvid>-<cid>`**，而且 `cid` 会在**任何入口**补齐后再算键
（「点歌 b站 关键词」的搜索结果里本来没有 cid）。这条口径很关键：顺序反了的话同一个视频
会按两套键各存一份、互相不命中（实测 17.3MB × 2，界面上还显示"未缓存"）——
现在有源码级自检绊线钉住它，改坏了会立刻红。

### 歌词缓存与旁车歌词

**歌词缓存和音频缓存是同一个子系统**（同一目录、同一份统计、同一个「清空缓存」），
存在 `data/cache/lyrics/`。缓存歌词不只是为了快 —— 网易云按 IP 限流，
反复搜同一批歌很容易把你自己打进「操作频繁」，表现就是"本来有歌词的歌突然没歌词了"。

**网易云 / 本地 / B站 三种曲目的歌词都走这份缓存**（B站用它的音频键，本地用
`match-<歌名>`）：命中时来源显示「缓存」，本地完全不联网。B站那条尤其重要 ——
它的歌词要经过"字幕接口 + 网易云匹配"两次网络，不缓存的话每次切回来都重跑一遍。

**匹配到的歌词还会落到歌曲文件旁边**（`local.autoSaveLyrics`，默认开）：

| 文件 | 内容 | 说明 |
|---|---|---|
| `<歌名>.lrc` | 标准 LRC | 任何播放器都能用 |
| `<歌名>.trans.lrc` | 翻译 | 双语显示（有翻译时才写） |

**写出的只有这两个**（2026-09-26 起不再写 `.karaoke.lrc` —— 逐字染色下线后没人读它，
也少一次磁盘写入）。

读取时是**四条路径依次退化**：`<歌名>.lrc` → `<歌名>.karaoke.lrc`（旧版逐字文件，
**仍然照常读取**，只是里面的逐字时间戳不再用于渲染）→ `<歌名>.trans.lrc`（翻译）
→ 内嵌 USLT/LYRICS 标签。

规则：**只在文件不存在时写入，绝不覆盖你自己放的歌词**；目录不可写会优雅失败并记日志。
有了旁车歌词，这首歌以后**完全不联网**，也不受限流影响，歌搬到哪歌词跟到哪。

## 9. 配置与数据位置

**所有数据都在程序自己的目录下**，不写 C 盘用户目录：

```
<程序目录>/
  data/
    config.json     配置（含 cookie、黑名单、已导入歌单）
    covers/         本地内嵌封面抽取缓存
    cache/          在线媒体缓存（音频 + 歌词）
    logs.txt        运行日志（超 2MB 自动滚动一代 logs.txt.1）
    electron/       Electron 的 userData（缓存、Cookie、网易云登录会话）
```

> Electron 默认会把 userData 写到 `%APPDATA%\nekofm`。本项目在启动时用
> `app.setPath('userData', <程序目录>/data/electron)` 改了落点，
> 所以整套东西可以整个丢在别的盘（例如 `D:\nekofm`），换机直接拷走。
> 也可以用环境变量 `NEKOFM_DATA` 指定别处。

首次运行生成 `data/config.json`。改完重启生效；叠加层与信息栏样式支持热改。

仓库里的 [config.example.json](config.example.json) 是**从 `DEFAULT_CONFIG` 自动生成的**
（`npm run config:example`），可直接照抄；**全部字段的说明见
[docs/CONFIGURATION.md](docs/CONFIGURATION.md)**。下面是节选（只列最常改的）：

```jsonc
{
  "server": { "port": 37821 },
  "netease": { "cookie": "（扫码后自动写入，别手填）", "level": "exhigh", "encodeType": "aac" },
  "bilibili": {
    // 弹幕通道二选一：openlive（需自备开发者凭证）/ browser（需本机有 Edge 或 Chrome）
    "danmakuMode": "openlive",
    "roomId": "你的直播间号（只对 browser 通道有效）",
    "autoConnect": true,
    "openLive": {
      "enabled": false,
      // 这四项都要自己在 open-live.bilibili.com 申请，且弹幕消息类型要单独开通
      "accessKeyId": "", "accessKeySecret": "", "appId": "", "roomOwnerAuthCode": ""
```

## 10. 故障排查

| 现象 | 原因与处理 |
|---|---|
| 歌词只显示 45 秒就没了 | 会员曲未登录 → 控制台扫码登录网易云 |
| 叠加层一直空白 | 确认 NekoFM 在运行；地址必须是 `/overlay`；看控制台「提示/日志」 |
| 直播姬里歌词不刷新 | 浏览器源需允许访问 `127.0.0.1`；点控制台「应用并保存」会重新广播配置 |
| 歌词比声音慢/快 | 调「歌词偏移」（毫秒，正值=歌词延后） |
| B站视频没声音 | 该视频可能没有独立音频流；看日志里的错误提示 |
| 弹幕收不到（浏览器通道） | 程序会自动拉起**系统 Edge / Chrome**（屏幕外窗口）；**两者都没装就收不到** —— 这种情况请改用官方通道或装一个 Chromium 系浏览器。再看房间号与页头的连接状态 |
| 弹幕收不到（官方通道） | 凭证配全了吗？**最常漏的是"弹幕消息类型"要单独向 B站运营申请开通** —— 长连能建立但一条弹幕都不推 |
| 切了通道却没生效 | `danmakuMode` 选 `openlive` 但凭证不全时**会自动回落到浏览器通道**，界面会提示；补全 `openLive` 四项并重启 |
| 弹幕昵称是 `L***`（一堆星号） | 说明这条连接被 B站当成了**游客**。程序会用 `bilibili.cookie` 里的 `DedeUserID` 自动带上身份；若仍打码就是 **cookie 过期/未填** → 控制台「登录 B站」重新扫码或粘贴 SESSDATA。另：**打码昵称不参与"认主播"判断**（`L***` 不唯一，认了会把路人当主播），认主播以房间房主 uid 为准 |
| 设备下拉是空的 | 播放核心窗口需先授权音频设备；点「刷新」 |
| 找不到端口 | 端口被占用会自动 +1，看启动日志里的实际地址 |
| **打包版出问题但"没有控制台"** | 托盘右键或窗口菜单 → **「运行日志 / 状态」**：实时日志 + 播放/队列/弹幕/网易云/缓存状态都在里面；日志同时落盘 `data/logs.txt`（可直接发给别人看） |
| **主播发指令被判"没有权限"** | 程序靠房间信息里的**房主 uid** 认主播（昵称兜底，且昵称带星号时**不参与**判断 —— 打码名不唯一，乱认会把路人当主播）。弹幕状态 pill 的 tooltip 会写"已认出主播：昵称 · uid"；运行日志里还会记「主播身份」「弹幕身份样本」两行，一眼看出没认出来的原因。另：B站**未开播时不推送任何弹幕**，此时发指令不会有反应 |
| **单独信息卡窗口空闲时一片空白** | 设计如此（没在播就不往画面上放卡片）。要在空闲时预览样式，用控制台菜单里的「预览：只要信息卡片」——那个窗口会显示一套示例内容，勾选开关能当场看到效果 |
| **升级 exe 后直播姬里还是老样子** | 直播姬的浏览器源挂着旧页面，不会随程序升级重载。现在程序会在 SSE 重连时带上资源版本戳，页面会在**歌曲间隙自动重载**；本次升级前的旧页面需**手动刷一次源**（右键 → 刷新/重新加载） |
| **双击绿色版 exe 后"信息全丢"** | 十有八九是**数据联接没了**（打包会清掉它）—— 绿色版在 exe 同目录新建了一份空 `data`，你的数据还在项目根的 `data/` 里没动。删掉那份新建的空 `data`，跑 `npm run link-data` 恢复。详见第 2 节第 27 条 |

## 11. 合规提示

- 播放内容请自行确认版权；B站直播规范要求**标注音乐来源出处**。
- 本项目只使用**你自己账号**的登录态取流，不内置任何绕过版权/会员限制的手段，
  也不分发音频文件、歌词与直链。仓库里不含任何音频与 cookie。
- **弹幕的两条通道都是正规途径**：
  - 官方直播开放平台 —— B站**面向开发者**的接口，主播授权自己的直播间完全合规；
    但**凭证（含弹幕消息类型）需要由使用者自行申请开通**，本项目不附带任何凭证。
  - 浏览器通道 —— 与你在浏览器里打开自己直播间看弹幕是同一件事，
    只是把"接收"这件事放到了屏幕外的窗口里。
- 请自行遵守所接入平台的服务条款。
